# 테이블 오더 제품 명세

작성일: 2026-09-09

상태: 사용자 구현 승인 이후 구현한 제품의 설계 기준. 안정성·대형 매장 UX, 터치 중심 조작, 수신 단말과 독립적인 주문 접수·자동 backfill을 반영했다. 실제 구현·검증 결과와 실물 장비·인프라 측정 한계는 [검증 보고서](verification.md), 구체적인 운영·집계 규칙은 [운영 가이드](operations.md)를 따른다. 아래 목표를 모두 실측 통과했다는 의미는 아니다.

## 1. 제품 목표와 운영 범위

- 한 매장에 독립 설치하는 손님용 모바일 웹과 직원용 대시보드.
- 실제 결제 연동 없이 매장 밖에서 이루어진 수납 결과를 기록한다.
- Bun, SolidJS, TypeScript, Biome, Elysia, PostgreSQL, Drizzle, Caddy, Podman을 기본으로 한다.
- Linux 서버와 공개 도메인을 사용하는 설치를 기본으로 한다. 공개 서버 방식은 손님이 매장 Wi-Fi 없이 QR을 사용할 수 있다는 전제다.
- 배달의민족을 참고한 손님 주문 UX와 Preline을 참고한 직원 대시보드 스타일을 공통 디자인 토큰으로 구성한다.
- 우선순위는 주문·금액의 정확성, 장애 시 확인 가능한 상태, 직원의 처리 효율, 응답 속도, 시각적 완성도 순이다. 모든 항목을 납품 범위에 포함한다.
- 영업 중 일반 작업은 키보드 입력 없이 터치·클릭으로 완료한다. 안정성은 서버의 검증·복구로 확보하고 직원에게 매번 확인창·추가 입력을 요구하는 방식에 의존하지 않는다.
- 직원 수신 단말이 0대여도 서버·DB가 정상이고 매장이 주문 접수를 허용한 상태라면 주문을 받는다. 단말 연결·heartbeat·알림 수신 여부는 주문 허용 조건에 넣지 않는다.

## 2. 핵심 모델과 불변 규칙

| 개념 | 책임 |
| --- | --- |
| 매장 | 영업·주문 접수 설정, 기본 통화 KRW, 시간대 Asia/Seoul, 영업일 마감 시각 |
| 구역 | 층·홀·룸 같은 테이블 그룹. 사용하지 않으면 전체 테이블로 표시 |
| 테이블 | 고정된 물리적 자리와 QR. 테이블당 진행 중인 방문은 최대 1개 |
| 방문 | 한 팀의 착석부터 종료까지. 인원, 주문, 정산, 접속 권한의 기준 |
| 주문 | 손님 또는 직원이 한 번 제출한 요청. 한 방문에 여러 주문 가능 |
| 주문 항목 | 주문 당시 메뉴명·옵션·단가의 사본, 주문·취소·조리·서빙 수량 |
| 정산 기록 | 외부에서 받은 수납을 기록. 금액·수단·시각·처리자·정정 이력 |
| 활동 이력 | 추가·취소·서빙 정정·이동·정산 등 주요 변경과 처리자 |
| 운영 알림 | 확인 여부를 DB에 보존하는 업무 기록. 브라우저 팝업 수명과 독립 |

- 가격·합계는 서버에서 원 단위 정수로 계산한다. 주문 당시 가격은 이후 메뉴 수정과 분리한다.
- 주문 항목의 취소 수량은 주문 수량을 초과할 수 없다. 조리·서빙 수량 변경도 서버에서 상태와 잔여 수량을 확인한다.
- 이미 서빙한 항목의 금액을 취소할 때는 일반 미조리 취소와 구분하여 사유와 이력을 남긴다. 판매 수량과 실제 서빙 이력을 따로 집계한다.
- 손님 두 명의 동일한 메뉴 주문은 정상적인 별도 주문이다. 같은 요청의 재전송만 중복 제거한다.
- 테이블 종료, 취소, 정산 중 동시 주문이 들어오더라도 하나의 일관된 결과가 남아야 한다.
- 정산 후 주문은 잠긴다. 정산 정정은 권한과 사유를 확인하고 원 기록을 보존한다.
- 이력이 있는 메뉴·테이블은 운영 화면에서 제거하되 과거 기록을 보존한다. 진행 중인 방문이 있는 테이블은 삭제할 수 없다.
- 손님의 권한은 방문에 묶는다. 다른 테이블이나 이후 방문을 열람할 수 없어야 한다.

## 3. 테이블과 주문 운영

기본 흐름: QR에서 바로 주문 → 새 주문 확인 → 음식 나감 → 수납 기록과 동시에 테이블 비움.

- 테이블 상태는 빈 테이블 / 손님 있음 두 가지로만 표시한다.
- 정산 상태는 미정산 / 정산 완료로 별도 표시한다. 돈을 냈지만 아직 식사 중인 상황을 표현할 수 있다.
- 주문은 새 주문 / 준비 중 / 음식 나감으로 요약한다. 기본 모드에서 확인 버튼을 누르면 준비 중으로 전환하므로 접수와 조리 시작을 각각 누르지 않는다. 항목별 잔여·서빙·취소 수량은 서버가 계산한다.
- 손님이 첫 주문을 확정할 때 방문을 자동 생성하고 테이블을 손님 있음으로 바꾼다. 메뉴 열람만으로는 테이블을 점유하지 않는다. 인원은 나중에 선택할 수 있고 미입력을 임의의 인원으로 채우지 않는다.
- 직원 추가 주문은 메뉴 선택과 이름·가격을 직접 입력하는 임의 항목을 지원한다.
- 취소는 항목·수량과 손님 요청 / 잘못 주문 / 품절 등의 사유 버튼으로 처리한다. 자유 입력은 기타 설명이 필요할 때만 사용한다. 손님 화면에도 취소된 항목과 변경된 합계를 표시한다.
- 정산 화면은 최신 주문·금액을 확인하고 방문 버전을 검증한다. 확인 도중 추가 주문이 오면 변경 내용을 보여주고 다시 확인받는다.
- 현장 수납을 기록하면 방문을 종료하고 테이블을 즉시 빈 상태로 바꾼다. 별도 퇴석·정리 완료 단계는 두지 않는다.
- 테이블 이동은 빈 목적지로만 허용한다. 방문·주문을 유지하며 원래 테이블은 비운다. 양쪽 테이블을 한 번에 갱신한다.
- 이동 후 원 테이블 QR로는 이동한 방문에 새로 참여할 수 없다. 기존 참여자의 화면은 새 테이블 번호로 갱신되고, 방문 종료 시 모두 만료된다.
- 일반 정산은 테이블 상세에서 최신 금액을 확인한 뒤 카드·현금·이체·기타 수단을 누르는 두 단계다. 마지막 버튼은 외부 수납 완료와 테이블 비움을 함께 기록하는 명시적 확정 동작이다.
- 일반 경로에 별도의 세 번째 확인 모달을 추가하지 않는다. 미서빙·추가 주문·상태 충돌 등 실제 예외가 있을 때만 해결을 요구한다.

## 4. 직원 화면과 대형 매장 UX

### 테이블 현황

- 기본 진입 화면은 테이블 현황이다. 테이블 번호, 구역, 인원, 이용 시간, 누적 금액, 새 주문, 미서빙 수량을 표시한다.
- 일상 작업의 주 화면은 홀 / 주문·주방 / 정산이다. 메뉴 편집·통계·계정·고급 설정은 보조 탐색으로 분리한다.
- 구역·층 필터, 테이블 번호 검색, 새 주문 / 미서빙 / 정산 대기 / 빈 테이블 필터를 제공한다.
- 테이블 배치는 안정적으로 유지한다. 실시간 변경으로 클릭 직전 카드가 다른 위치로 이동하지 않는다.
- 테이블 선택 시 상세 패널을 열고, 닫았을 때 기존 구역·검색·스크롤 위치를 복원한다.
- 새 주문 색상만으로 상태를 전달하지 않고 텍스트·아이콘·개수를 함께 표시한다.

### 주문·주방 화면

- 카운터·홀은 테이블 중심, 주방은 미처리 주문 중심으로 같은 데이터를 본다. 두 앱 외에 별도 앱을 추가하지 않는다.
- 큰 글씨의 테이블 번호, 주문 시각, 대기 시간, 요청사항, 수량을 우선 노출한다.
- 기본은 오래 기다린 미처리 주문 우선이다. 갱신 때문에 사용자가 누르려는 행이 바뀌지 않게 새 주문 배지를 제공한다.
- 새 주문 확인, 조리, 서빙은 다른 행동이다. 화면을 열었다고 접수·서빙 완료로 처리하지 않는다.
- 기본 모드에서는 확인과 음식 나감 두 버튼 조작으로 주문 처리를 끝낸다. 확인은 직원 인지와 준비 시작을 함께 기록한다. 조리 시작·조리 완료를 따로 관리하는 세부 모드는 원하는 매장만 설정에서 켠다.
- 누가 접수·처리했는지 표시하고, 여러 직원의 동시 조작은 중복 적용하지 않는다.
- 주문 전체와 선택한 항목·수량별 처리를 제공한다. 일괄 작업은 대상 테이블과 수량을 명확히 표시한다.
- 주방·음료 등 필요한 항목 필터와 구역 필터를 지원한다. 필터 밖의 미확인 주문 개수도 표시한다.
- 소리·배지·미확인 목록을 함께 제공한다. 새 주문마다 화면을 가리는 모달을 띄우지 않는다.
- 오래 미확인된 주문은 단계적으로 강조한다. 반복 소리는 상한을 두고, 담당 단말과 다른 단말의 알림 방식을 구분한다.
- 소리를 활성화하는 시작 동작과 테스트를 제공한다. 브라우저·OS의 절전이나 음소거를 웹 앱이 강제로 해제할 수 있다는 가정을 하지 않는다.
- 첫 설정에는 테스트 주문으로 소리·주문 표시·처리 흐름을 점검할 수 있는 안내를 제공한다. 테스트 데이터는 운영 매출과 분리한다.

### 입력·실수 복구

- 일반 주문 확인·서빙은 최소 조작으로 처리한다. 취소·정산 정정처럼 금액을 바꾸는 작업에는 구체적인 확인을 둔다.
- 수량은 +/-와 자주 쓰는 수량 버튼, 인원은 선택 버튼, 사유는 프리셋, 이동은 테이블 카드 선택으로 처리한다. 테이블 이름·번호는 생성 시 자동 제안한다.
- 입력이 필요한 메뉴 등록·가격 편집은 영업 준비 기능이다. 영업 중 이름·금액을 타이핑하는 임의 주문과 자유 메모는 예외 경로로 둔다.
- 저장 실패 시 입력을 보존한다. 로그인 갱신 후에도 작성 중이던 작업으로 돌아올 수 있게 한다.
- 되돌리기는 취소 버튼으로 화면만 복원하지 않는다. 서버의 현재 상태·권한·변경 이력을 검증하는 정정 작업으로 수행한다.
- 잘못 누른 음식 나감은 짧은 시간 동안 되돌리기를 제공한다. 사이에 다른 직원의 후속 변경이 있으면 덮어쓰지 않고 최신 상태를 안내한다. 정산 정정은 이 간편 되돌리기와 분리한다.
- PC 키보드, 태블릿 터치, 작은 화면을 지원하고, 주요 조작 영역은 충분히 크게 만든다.
- 로딩·빈 목록·오류·연결 복구 상태를 각각 디자인한다. 조작 결과는 서버 확인 전까지 확정 상태로 표시하지 않는다.

## 5. 손님 주문 UX

- 매장명과 테이블 번호를 모든 핵심 화면에서 확인할 수 있게 한다.
- 메뉴 사진·이름·가격·설명, 상세, 수량, 요청사항, 장바구니, 최종 확인, 주문 내역을 제공한다.
- 카테고리는 관리자 설정으로 표시·미표시를 전환한다. 미분류 메뉴도 누락되지 않게 표시한다.
- 장바구니는 휴대폰별이다. 제출한 주문은 같은 방문의 참여자가 공유한다.
- 품절·가격 변경은 최종 제출 때 서버에서 재검증한다. 바뀐 항목을 알려주고 확인 없이 인상된 가격으로 주문하지 않는다.
- 주문 결과는 전송 중 / 저장 확인 중 / 주문 완료 / 주문되지 않음으로 구분한다. 결과가 불명확하면 실패나 성공으로 단정하지 않는다.
- 성공한 주문에는 주문 번호와 접수 대기 상태를 표시한다. 주문 완료는 DB 저장 완료이며 직원 접수와 구분한다.
- 연결이 끊기면 장바구니와 요청 식별자를 보존한다. 복구 후 이전 제출 결과를 먼저 확인한다.
- 아직 제출하지 않은 장바구니는 연결 복구 시 임의로 전송하지 않는다. 자동 백그라운드 주문 큐는 두지 않는다.
- 손님 직접 취소는 기본 범위에 포함하지 않는다. 직원에게 요청하라는 안내와 직원 처리 결과를 제공한다.
- 정산 또는 방문 종료 뒤에는 새 주문을 허용하지 않고 현재 상태를 안내한다.

## 6. 수신 단말과 독립적인 접수·자동 backfill

- 서버의 주문 접수와 직원 단말로의 실시간 전달을 분리한다. 관리자 앱이 모두 닫혀 있거나 매장 인터넷이 끊겨도 손님이 서버에 접근할 수 있으면 정상적으로 주문한다.
- 주문·항목·알림에 필요한 변경 기록을 DB에 저장한 뒤 손님에게 주문 완료를 표시한다. 직원 단말 응답이나 수신 확인을 기다리지 않는다.
- 미확인 주문은 직원이 확인할 때까지 DB에 남긴다. 알림 전송, 화면 열기, 연결 복구만으로 확인 처리하지 않는다.
- 단말 연결 상태는 직원용 진단 정보다. 연결이 끊겼다는 이유로 고객 화면에 주문 불가나 서비스 중단을 표시하지 않는다.
- 단말은 재연결·새로고침·새 기기 로그인 시 놓친 변경과 현재 미처리 주문을 자동으로 불러온다. backfill 버튼이나 수신 재개 확인을 매번 요구하지 않는다.
- 복구 중에도 새 주문은 계속 받는다. backfill 종료와 실시간 구독 전환 사이에 생긴 주문도 포함한다.
- 다른 단말에서 확인·취소·서빙한 내역을 함께 반영한다. 오래된 새 주문 이벤트만 재생해 이미 처리한 주문을 다시 미확인으로 만들지 않는다.
- 누락분이 많으면 오래 기다린 미확인·미처리 주문을 먼저 보여주고, 복구한 미확인 주문 N건처럼 한 번에 안내한다. 과거 알림 소리를 주문 수만큼 연속 재생하지 않는다.
- 복구한 목록을 확인했다고 자동 서빙·정산하지 않는다. 일반 확인·음식 나감 버튼 흐름을 그대로 사용한다.
- 서버 또는 손님 자신의 네트워크에 실제 장애가 있는 경우는 별도로 구분한다. 서버 저장이 확인되지 않은 요청을 주문 완료로 표시하지 않는다.
- 장애 중 직원이 직접 받은 주문은 복구 후 기존 주문·시간·테이블을 대조한 뒤 기록할 수 있게 한다.

## 7. 메뉴·QR·정산·통계·권한

- 메뉴 사진 업로드·교체, 이름·가격·설명 CRUD, 품절·노출·정렬, 카테고리 CRUD를 제공한다.
- 정산은 테이블 전체 일괄 수납 기록, 카드·현금·이체·기타를 기본으로 한다. 분할 수납·실제 결제·환불 연동은 별도 범위다.
- 정산 내역과 기간별 수납액, 메뉴별 판매 수량·금액, 취소 수량·금액, 방문 팀·인원, 평균 정산액, 시간대 추이를 제공한다.
- 주문·서빙·수납·정정 시각을 구분한다. 영업일 경계와 정산 정정의 집계 규칙을 구현 전에 예시로 확정한다.
- 임의 항목은 판매 내역에 포함하되 정규 메뉴 순위와 구분한다. 정산 취소를 실제 외부 환불로 표현하지 않는다.
- 메뉴·통계는 이력을 기준으로 집계하며 현재 메뉴 데이터만으로 과거를 재계산하지 않는다.
- QR 포스터는 매장명·로고, 테이블 번호, 주문 안내 문구, 스캔 안내, 포인트 컬러를 포함한다.
- 개별 A6 PDF·고해상도 PNG, 전체 테이블 A4 배치 PDF와 미리보기를 제공한다. 실물 출력·스캔을 검증한다.
- 점주·직원 권한을 구분한다. 직원은 주문·테이블 운영, 점주는 메뉴·통계·계정·설정과 정산 정정을 관리한다.

## 8. 아직 구체적인 선택이 없었던 부분의 제안값

- 기본 메뉴·수량·요청사항부터 구현한다. 복합 옵션·토핑·사이즈는 별도 확정이 없으므로 현재 기본 범위에 넣지 않는다.
- 고정 QR을 열면 입장·방문 생성 화면 없이 바로 메뉴를 표시한다. 방문은 첫 주문과 함께 서버에서 자동 생성한다.
- QR만으로 접속하는 간편 모드는 고정 URL을 보관한 사람이 이후에도 접근할 수 있다는 한계를 설정에서 설명한다. 방문 종료만으로 고정 URL의 재참여까지 차단된다고 주장하지 않는다.
- 방문별 접속 권한 만료는 어떤 모드에서도 적용한다. 운영자가 빈 테이블의 방문을 시작하기 전에는 손님이 임의로 주문을 시작할 수 없다.
- 다국어, 회원·포인트, POS·영수증 프린터 연동, 배달·포장, 여러 매장 통합 관리는 현재 범위에 포함하지 않는다.

## 9. UI 방향

- 손님: 사진과 메뉴 탐색 중심, 밝은 배경, 민트·청록 포인트, 둥근 카드, 명확한 가격, 고정 장바구니 버튼.
- 직원: Preline을 참고한 사이드바·표·폼·상태 배지, 구역별 테이블 카드와 작업 목록. 장식보다 식별·처리 속도를 우선한다.
- 공통: 한국어 가독성, 일관된 간격·색상·모서리·타이포그래피, 키보드 초점·레이블·상태 안내, reduced-motion 지원.
- 손님 화면 360~430px, 직원 태블릿 세로·가로와 데스크톱에서 실제 흐름을 검증한다.
- 직원 태블릿의 주요 터치 버튼은 최소 48 CSS px를 목표로 하고 충분한 간격을 둔다. 아이콘만으로 조작을 추측하지 않게 짧은 한글 동작명을 표시한다.
- 카드당 지금 필요한 주 동작을 우선 노출하고 예외 동작은 상세·더보기로 둔다. 데스크톱 hover, 우클릭, 드래그, 단축키를 필수 조작으로 만들지 않는다.
- 직원에게는 손님 있음 / 빈 테이블 / 확인 / 음식 나감 / 정산 같은 매장 용어를 사용한다. 방문 세션·이벤트·동기화·버전 같은 구현 용어를 정상 업무 화면에 노출하지 않는다.

## 10. 기본 모드의 조작 예산

아래 횟수는 표에 명시한 시작 화면부터 세는 일반 경로의 목표다. 화면 탐색이나 실제 상태 충돌을 해결하는 추가 조작은 별도로 측정한다.

| 업무와 시작 화면 | 조작 목표 | 필수 키보드 입력 |
| --- | --- | --- |
| 손님의 첫 주문 | 메뉴 담기와 주문 확정만 수행, 방문은 자동 생성 | 없음 |
| 새 주문 카드에서 확인 | 확인 1회, 준비 중 전환·직원 기록은 자동 | 없음 |
| 준비 중 카드에서 전체 음식 나감 | 음식 나감 1회, 서버 확인 후 반영 | 없음 |
| 테이블 상세에서 카드·현금 정산 및 비움 | 정산 열기 + 명시적인 수납 완료 버튼, 총 2회 | 없음 |
| 일부 수량 취소 | 항목 선택 → +/- 수량 → 사유 버튼 → 금액 확인·취소 | 없음 |
| 테이블 이동 | 이동 열기 → 빈 목적지 선택 → 번호 확인·이동 | 없음 |

- 새 주문 하나를 정상적으로 확인하고 전체 서빙하는 과정은 총 두 번의 터치가 목표다.
- 분리 조리 단계, 인원 필수 입력, 방문 입장 화면, 별도 퇴석·정리 단계, 모든 작업에 확인 모달은 기본 모드에 두지 않는다.
- 홀 담당자가 메뉴얼을 읽지 않고도 일반 주문·취소·정산을 수행할 수 있는지 시나리오로 확인한다. 필수 타이핑, 되돌아가기, 버튼 찾기가 생기는 지점을 기록하고 줄인다.

상세 장애 대응, 부하 기준, 배포 범위와 구현 단계는 [안정성 및 실행 계획](implementation-plan.md)을 따른다.
