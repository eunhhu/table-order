# QR 진입과 방문별 주문 권한

## 적용 범위

고정 QR 원본 URL을 고의로 재접속하는 사람의 물리적 위치까지 인증하지는 않는다. 이 변경의 목표는 **계산 후 남아 있는 메뉴 탭, 브라우저 재실행, 늦은 미확인 주문 재전송이 다음 방문으로 넘어가지 않게 하는 것**이다.

인쇄된 `/t/:qr`는 유지한다. 고객 앱은 이 진입 주소에서만 `/api/guest/:qr/enter`로 이동하고, 서버는 쿠키를 발급한 뒤 `303`으로 `/menu/:qr/:page`에 보낸다. 최종 메뉴 페이지와 모든 조회·주문 API는 권한을 자동 재발급하지 않는다. 종료 화면에도 진입 주소로 자동 이동하는 링크를 두지 않는다.

## 방문 시작 시점 변경

방문은 첫 주문이 아니라 **첫 QR 진입 시점**에 열린다. 같은 테이블의 여러 기기가 동시에 진입해도 기존 주문·정산과 같은 매장 행 잠금 안에서 하나의 방문을 공유한다. 아직 주문하지 않은 기기와 최초 주문의 미확인 요청도 처음부터 특정 방문에 묶인다.

따라서 QR만 보고 주문하지 않아도 테이블은 이용 중으로 표시된다. 주문 없이 퇴장한 팀은 직원이 빈 방문을 종료해야 한다. 주문 유무와 무관하게 테이블 회전 경계를 명시적으로 닫아야 한다. 방문 수·시작 시각 통계도 QR 진입 기준이 된다. 장바구니나 쿠키 만료만으로 방문을 자동 종료하지는 않는다.

## 서버 불변 조건

- 쿠키에는 난수 bearer credential만, URL에는 `SHA-256(qr + ':' + credential)` 식별자만 둔다. 식별자만으로 인증되지 않는다. DB에는 식별자 해시와 방문 연결을 보관한다.
- 모든 고객 API는 쿠키, QR, 페이지 식별자, DB 만료를 확인한다. 다른 탭에서 같은 이름의 쿠키가 바뀌어도 이전 페이지의 식별자는 바뀌지 않아 만료 처리된다.
- 주문 대상은 인증된 방문 ID로만 결정한다. HTTP 주문 입력에서 `visitId`는 제거하고, 기존 트랜잭션의 `createOrder`가 방문의 `open` 상태를 다시 확인한다. 내부 호환용 `GuestOrder.visitId`는 HTTP 권한으로 사용하지 않는다.
- snapshot은 주어진 방문만 읽는다. 닫힌 방문에서 테이블의 현재 방문으로 대체하지 않는다. SSE도 인증된 방문으로 범위를 고정한다.
- 주문 결과 조회는 같은 방문의 이미 저장된 요청을 확인할 수 있다. 닫힌 방문의 새 주문은 거절하며, 결과 조회로 방문이나 쿠키를 생성하지 않는다.

테이블 이동 후에도 기존 권한은 방문을 따라간다. QR를 해시 입력에 포함하므로 cookie 이름만 바꿔 다른 QR의 권한처럼 사용할 수는 없다. 같은 브라우저에서 재스캔하면 새 페이지가 발급되며 그 QR의 이전 메뉴 탭은 만료된다.

## 만료와 복구

서버 권한의 절대 수명은 12시간이다. 정산·방문 종료·전체 주문 취소로 방문이 닫히면 그 전에 만료된다. 쿠키가 남아 있거나 사라져도 최종 메뉴 페이지는 새 권한을 받지 않는다.

장바구니·요청사항·pending 저장 키는 QR와 페이지 식별자로 분리한다. 종전 테이블 단위 저장 데이터를 새 페이지로 가져오지 않는다. pending은 기존 요청 ID로 접수 결과를 먼저 확인하고, 결과가 없을 때만 15분 이내 자동 재전송한다. 이후에는 직원 확인을 안내한다. 이 시간 제한은 사용자 경험을 위한 클라이언트 정책이고, 방문 간 격리는 서버가 보장한다.

## 배포와 검증

DB 스키마 변경이나 QR 재인쇄는 필요하지 않다. API와 고객 앱을 함께 배포한다. 이전 앱의 쿠키·요청에는 새 페이지 식별자가 없으므로 다시 QR로 진입해야 한다. 기존 미확인 주문은 중복 주문하지 말고 관리자 주문 내역으로 확인한다.

중요한 전환 한계: 옛 버전의 메뉴 주소 자체가 `/t/:qr`였으므로, 옛 탭에서 이 주소를 새로 로드하는 행동과 QR 재스캔은 구별할 수 없다. 새 `/menu/:qr/:page` 흐름으로 발급된 페이지부터 만료 보장이 적용된다. 영업 사이에 배포하고 기존 탭은 닫도록 안내한다. 고정 QR 원본을 저장해 고의로 다시 여는 경우도 이 변경의 위협 모델 밖이다.

`tests/integration/guest-pages.test.ts`는 방문 교체, 주문 전 기기, 동시 진입, 만료·누락 자격 증명, 쿠키 교체, 이동, QR 범위, 입력 방문 ID, 멱등 결과 조회를 검사한다. 기존 복구 테스트와 부하·컨테이너·배포 검증 도구도 새 진입 방식을 사용한다.

전체 검증 명령은 기존과 동일하다.

```sh
bun run test:db
bun run check
```

본 패치 작성 환경에서는 Bun·PostgreSQL과 의존성 설치가 불가능하여 전체 타입 검사·통합 테스트·부하 테스트를 실행하지 못했다. 로컬 TypeScript/TSX 구문 검사와 pending 시간 경계의 독립 실행 검사를 수행했다. 기존 성능 보고서를 이 변경의 실측 결과로 간주하지 않는다. 병합 전 CI와 별도 매장 검증 환경에서 전체 검사를 완료해야 한다.
